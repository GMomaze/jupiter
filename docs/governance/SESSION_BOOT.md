# Jupiter Mandatory Session Boot

**Document ID:** JUPITER-SESSION-BOOT

**Revision:** 1.0

**Status:** Canonical

**Effective date:** 2026-08-17

Complete these steps in order before performing project work:

1. Read repository-root [`AGENTS.md`](../../AGENTS.md).
2. Read [`GOVERNANCE_INDEX.md`](GOVERNANCE_INDEX.md).
3. Read [`JUPITER_AI_DEVELOPMENT_CONSTITUTION.md`](JUPITER_AI_DEVELOPMENT_CONSTITUTION.md).
4. Record repository path, branch, HEAD, index, modified files, and untracked files.
5. Identify pre-existing and user-owned work; record any overlap with the task.
6. Read [`MASTER_EXECUTION_PLAN.md`](MASTER_EXECUTION_PLAN.md).
7. Read [`CURRENT_SYSTEM_ROADMAP.md`](CURRENT_SYSTEM_ROADMAP.md).
8. Read [`ACTIVE_WORK.md`](ACTIVE_WORK.md).
9. Read the exact active approved feature/phase plan and current owner instruction.
10. Inspect applicable source, migrations, tests, database catalog, and runtime evidence.
11. Before any potentially destructive command, confirm authority, exact target,
    safe command, test/database environment, backup or recovery requirements, and
    stop conditions. Apply the database and verification policies when relevant.
12. Stop if authority, scope, evidence, target, or safe execution cannot be established.

Do not read the entire documentation tree by default. Historical and domain
documents are loaded only when relevant to the approved work.

Before implementation, state the active phase/slice, mode, existing-functionality
classification, expected files, user-owned overlaps, and verification boundary.
