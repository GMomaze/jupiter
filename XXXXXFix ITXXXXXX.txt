1. Critical Schema Drift
- `src/models/core/Aircraft.ts` expects fields such as `loaded_into_system_at`, `manufacture_date`, `tcds_number`, `tcds_url`, and `photo_url`.
- Fresh and existing databases can fail if these columns are missing.
- Fix:
  Run and keep `migrations/271_add_aircraft_document_fields.ts`.

- `src/models/ComponentModel.ts` expects:
  `model_code`, `service_interval_hours`, `service_interval_months`, `overhaul_interval_hours`, `overhaul_interval_months`, `maintenance_notes`, `is_life_limited`, `is_active`.
- Older schemas did not create the full shape of `component_models`.
- Fix:
  Keep `migrations/100_expand_aircraft_and_components.ts` aligned with the model.
  Keep `migrations/260_expand_manufacturers_and_models_master_data.ts` for `model_code`.

- `src/models/core/TaskTemplate.ts` expects applicability flags:
  `is_required_for_wood`
  `is_required_for_fabric`
  `is_required_for_bungees`
  `is_required_for_woodprop`
  `is_required_for_retractable`
- Existing databases can fail on import and planner views when these columns are absent.
- Fix:
  Keep `migrations/231_add_task_template_applicability_flags.ts`.

- `src/models/core/WorkpackExecution.ts` and `src/modules/workpacks/workpack.service.ts` expect:
  `task_id`, `attempt_no`, `started_by`, `completed_by`, `certified_by`, `certified_at`, `version`
- The old `workpack_executions` table shape did not match current code.
- Fix:
  Keep `migrations/280_create-workpack-executions.ts` in its updated form.

- `src/models/audit/WorkpackSnagAuditLog.ts` and snag audit writes expect `workpack_snag_audit_log`.
- That table was missing.
- Fix:
  Keep `migrations/381_create_workpack_snag_audit_log.ts`.

- `src/models/ServiceBulletinSyncRun.ts` appears to expect `service_bulletin_sync_runs`, but no creating migration was previously found.
- Fix:
  Add a migration for `service_bulletin_sync_runs` if it still does not exist in the migration chain.

- This is a symptom, not the final fix.
